## Confirmed contract differences restored

1. **Gate before player access.** The original invokes its gate getter and returns null on a null result before reading `Minecraft.player`. The source now has the same early return ahead of the player access.
2. **Candidate scoring origin.** When the requested `BlockPos` is non-null, the original converts that position to a `Vec3` and uses it as the scoring origin. If the target is null or conversion returns null, it falls back to the player's position. The source now preserves this order and fallback rather than always starting at the player.
3. **Inclusive range and NaN behavior.** The original separately rejects `distance < min` and `distance > max`; equality at either boundary remains eligible, and NaN passes both comparisons. The prior negated inclusive-range expression rejected NaN. The source now uses the original independent rejection predicate.
4. **Kotlin default bridge is state-dependent.** The original collision call uses the static default bridge descriptor ending in `(…IZDZZDILjava/lang/Object;)Z`, with mask `368` and a literal scale placeholder `0.0`. The full bridge reads the same utility `c()I` gate. When that value is zero, the bridge skips default substitution and the effective scale stays `0.0`; when non-zero, mask bit `32` substitutes `1.0`. The other masked values resolve to the call site's already matching `false`/`0.0`, while the unmasked boolean remains `true`. Source now calls the same `c()I` getter for each eligible candidate and selects `1.0` or `0.0` accordingly before invoking the same core helper descriptor. This preserves both gate states instead of assuming the default branch is always active.
