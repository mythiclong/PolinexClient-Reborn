## Complete descriptor review

The original method spans bytecode offsets 0–933 and has 18 exception-table entries. All handlers catch `kotlin.NoWhenBranchMatchedException` and delegate to the owner's `a(Throwable): Throwable`; the complete helper is the identity (`aload_0; areturn`). The source uses direct control flow and does not swallow exceptions.

The entry reads the state gate first and returns null if it is null, then captures player and level in that order with null returns. It computes horizontal displacement from `param2` to `param3` and returns null below `1.0E-6`. The player collision AABB uses the configured radius, `y + 0.04`, and player height in the original coordinate/evaluation order.

For each collision shape, the source checks the iterator result before casting, then checks `bounds()` before using the returned AABB. It applies the same vertical-overlap comparisons, clamps the candidate x/z position to the obstacle bounds, computes the horizontal offset, and—when inside the obstacle—chooses the nearest face with the original minX, maxX, minZ, maxZ tie order. Obstacles whose nearest horizontal distance is greater than or equal to the configured radius are skipped. The remaining contribution is the normalized offset multiplied by the clamped penetration depth; there is no per-obstacle `0.28` scaling or per-obstacle maximum cap.

After aggregating all obstacles, the method removes the component along the requested travel direction, rejects a residual push shorter than `1.0E-4`, and applies `min(pushLength * 0.28, configuredMaximum)` exactly once to the normalized aggregate. It then adds that displacement to `param1`, restores the original `Intrinsics.checkNotNullExpressionValue(..., "add(...)")`, and returns the displacement only when the existing `b(Vec3)` walkability predicate accepts the new position.
