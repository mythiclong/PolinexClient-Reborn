## Confirmed source mismatches and corrections

### `h(Ljava/util/List;)Z`

The original increments the active route index first. When the shared gate is non-null it calls `g(List)`. Original `ifeq 45` skips stopping when `g(List)` is false; when true it invokes `v()`, returns false, and does not access the list at the completed index. The source had `!g(List)`, reversing those outcomes. The negation was removed. Final compiled bytecode now branches on the same predicate with `ifeq 34`; the ordered field references and invocation targets/descriptors match the original. Javac uses `invokevirtual` instead of Kotlin's `invokespecial` for private-final `g(List)` and `s()` calls; the owner is final.

### `g()V`

The original first reads the shared gate and returns on null before reading pending-route state. It then reads the volatile pending list and returns on null before reading the target or clearing either pending field. Only after both guards does it snapshot the target and clear pending list, then target, in that order. It next preserves the target/stop/enabled/empty-list checks before adopting the route. The source previously snapshotted and cleared both volatile fields before these guards. The method now restores the gate and pending-list guards before any target read or clear; the final compiled method preserves all 22 ordered field references.

The asynchronous result writer stores the target first and pending list second. Keeping the original null-list early return prevents a partially published result from being cleared or passed to `List.isEmpty()` before the route arrives. This ordering/race analysis is static; no runtime reproduction was performed.
